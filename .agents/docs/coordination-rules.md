# Codex 角色协作规则

按领域职责拆分工作：负责人组织跨领域决策，lead 协调部门实现，specialist 处理专业问题。
`team.size` 决定实际参与者，`review_mode` 决定评审深度，`modes.workflow` 决定产物要求；三者互不替代。
individual 模式可由核心角色整合咨询意见，不要求启动完整角色树。开始前说明实际参与集合与合并执行的角色职责。

同级角色可以咨询，但不擅自决定其他领域；冲突提交共同父代理，设计冲突由 creative-director、技术冲突由 technical-director 参与判断。
跨领域设计变更由 producer 协调传播，写入权限仍限任务明确指定的路径。
源码和产物需要独立写入时避免共享文件并发修改；只有输入与产出相互独立的任务并行，依赖结果先收齐再进入后续阶段。

委派使用当次 Codex 可用接口，详细运行约定见 `codex-runtime.md`。
简报包含任务、必要输入、可改文件、验收要求、产物路径及返回合同；按章节提供设计资料，避免重复灌入完整文档。
结果包含产物路径、简要结论、证据和 BLOCKED/CONCERNS 项。失败或缺产物立即报告，不以空输出当通过。
不可创建独立评审代理时明确未完成独立评审，不将同一实现者的自查算成独立结果。

委派前按角色 TOML 和当前模型目录解析所需型号，具体规则见 `model-tiers.md`。角色共享父会话的 sandbox 和账号权限限制。
对外 issue、PR 和消息默认先形成草稿；实际发送、发布或推送需要当前会话明确授权。
